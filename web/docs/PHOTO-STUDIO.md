# Фото товара и виртуальная примерка

## Подключение

1. Зарегистрироваться на https://app.fashn.ai/ . В Billing выбрать **FASHN API**,
   приобрести API credits. Обычная подписка приложения не заменяет API credits.
2. В Developer API dashboard создать API key. Инструкция:
   https://docs.fashn.ai/getting-started/api-setup . Сохранить ключ сразу:
   повторный просмотр после закрытия окна недоступен.
3. На сервере добавить в `/opt/vera-prive/.env` (для локального запуска — `web/.env`):

```dotenv
FASHN_API_KEY=your-private-key
PHOTO_MODEL_FRONT=https://your-host/reference-front.jpg
PHOTO_MODEL_BACK=https://your-host/reference-back.jpg
PHOTO_DAILY_LIMIT=30
```

Ключ не добавлять в dist, Git или сообщения. Референсы — HTTPS-фотографии одной
модели в двух ракурсах. Сейчас пара общая для магазина: подбирайте вещи под неё;
автоматического выбора модели по полу/возрасту нет. Для детских товаров эта пара
не подходит, если референс взрослый. Без референса соответствующая кнопка отключена.
Без ключа доступна обычная загрузка фотографий.

4. Пересоздать контейнер приложения из `web/deploy`: `docker compose up -d --build app`.
   Compose уже читает `.env`. Для локальной работы — перезапустить `npm start`.

## Использование

Открыть товар в кабинете администратора/поставщика. Загрузить до пяти исходных фото
через обычную загрузку; раскрыть «Подготовить фото с ИИ». Выбрать исходники переда,
спинки и деталей. Нажимать генерацию нужных кадров последовательно. Обработка
платная и никогда не стартует автоматически. Проверить каждый результат и нажать
«Использовать проверенные кадры», затем сохранить товар. Поставщик по-прежнему
отправляет товар на проверку администратору.

Порядок: товар на фоне, модель спереди, модель сзади (если создана), деталь,
оставшиеся оригиналы. Оригиналы сохраняются и в закрытых данных товара.
ИИ-кадры помечены в публичной галерее. Исходные URL для генерации не принимаются:
нужно загрузить файл. Фото сзади нельзя сделать без выбранного исходника спинки.
Не закрывать форму до применения и сохранения: задания переживают перезапуск
сервера, но несохранённый редактор после закрытия не восстанавливается.

## Реализация и ограничения пилота

FASHN `background-remove` даёт прозрачный PNG; браузер накладывает молочный фон
`#f3eee6` без генеративной перерисовки вещи. Этот endpoint имеет статус Experimental.
Примерка — `tryon-max`, 1k, balanced, один кадр (endpoint Preview).
Документация: https://docs.fashn.ai/api-reference/background-remove и
https://docs.fashn.ai/api-reference/tryon-max . Проверить качество на реальных фото:
точность логотипа, фактуры, пропорций и состояния не гарантируется API.

Задания хранятся в таблице photo_job существующей SQLite. Клиент опрашивает статус;
автоматического повтора платного POST нет. Ошибка сети при запуске может означать,
что запрос уже принят: проверить dashboard перед новым запуском. Лимит общий на
магазин, по умолчанию 30 запусков за скользящие 24 часа, включая неудачные попытки;
один активный запуск на пользователя. Лимит — число кадров, не денежный бюджет.
Установленные параметры: 1 credit за фон, 2 за каждый tryon-max; полный комплект
обычно 5 credits, по документации на 2026-11-15. Проверять текущую цену в dashboard.

Результаты запрашиваются в base64 и сохраняются локально, временные CDN-ссылки в
каталог не попадают. Допустимый результат до 3 млн символов; крупный PNG может
потребовать уменьшения исходника. Задания/результаты пока не очищаются автоматически:
следить за размером SQLite и резервных копий перед массовой обработкой.
Ни реальные платные запросы, ни публикация на VPS при разработке не выполнялись.

## Обновление 2026-11-15: прогресс и диагностика

Редактор показывает миниатюру исходника, этапы отправки/очереди/генерации/подготовки
результата и прошедшее время. Процент генерации не выдумывается: API его не сообщает.
После terminal failure форма разрешает новый запуск; после сетевой ошибки проверки
сохраняет возможность проверить прежнее задание, без повторного платного POST.
Большой ответ до 20 млн символов принимается для сжатия в браузере; после сжатия
каждый кадр занимает менее 450 тыс. символов. В каталоге прежний лимит не увеличен.
Коды отказа FASHN сохраняются в photo_job.errorCode; ключи, provider messages и
содержимое фотографий в диагностические сообщения не выводятся. Старые ошибки,
полученные до обновления, восстановить из базы нельзя: коды тогда не сохранялись.

Для проверки текущего ключа/баланса и последних заданий, без новой генерации:

```bash
cd /opt/vera-prive/deploy
docker compose exec -T app node server/photo-diagnostics.mjs
```

Документация ошибок: https://docs.fashn.ai/api-overview/error-handling
Категория аудитории «Унисекс» доступна в форме товара; такие вещи видны во «Все»,
«Женское» и «Мужское», но не в «Детское». Дополнительной вкладки унисекс нет.

## Передача исходника по временной ссылке

На VPS воспроизведено: POST на 1 КБ получает HTTP 400 (ожидаемый ответ на
некорректную модель), POST на 350 КБ получает ECONNRESET примерно через 15 секунд.
Ключ и баланс проверены отдельным GET: HTTP 200, 100 credits. Источник сетевого
сброса и связь с географией хостинга не установлены.

Теперь исходник хранится временно в SQLite photo_input, а FASHN получает короткий
HTTPS URL вместо data URI в POST. APP_URL должен быть публичным HTTPS-адресом
магазина; текущий Docker Compose уже задаёт https://shop.example.com.
Провайдер должен иметь возможность получить GET /api/photos/inputs/<token>.
Ссылка содержит случайный 256-битный токен; в БД сохраняется только его SHA-256.
Срок доступа — 20 минут. Неизвестный/просроченный токен возвращает 404; ответ
изображения не кэшируется. Просроченные записи удаляются при следующем запуске
обработки или запросе исходника. Оригиналы в карточке товара этим не затрагиваются.

Новый API-ключ и изменение PHOTO_MODEL_FRONT/BACK не нужны. После публикации
проверить одну реальную генерацию: локальные тесты не подтверждают сетевую
доступность временного изображения из инфраструктуры FASHN.

## Прокси для FASHN

Установлена фиксированная версия undici 8.12.4. Прокси применяется отдельным
ProxyAgent к запросам FASHN; OAuth, SMTP и прочий трафик магазина не затрагиваются.
Проверка TLS не отключается, при сбое прокси прямого повторного запроса нет.

Добавить на VPS в `/opt/vera-prive/.env`:

```dotenv
FASHN_PROXY_URL=http://LOGIN:PASSWORD@HOST:PORT
```

HTTP CONNECT передаёт HTTPS-трафик в туннеле; `http://` обозначает протокол
соединения с самим прокси, а не отключение HTTPS до FASHN. Использовать порт
HTTP-прокси из кабинета провайдера; для SOCKS5 можно использовать `socks5://` и
соответствующий порт. Спецсимволы логина/пароля должны быть URL-encoded.
Реальные учётные данные не хранить в Git и не выводить в терминал.

При наличии FASHN_PROXY_URL исходник передаётся в base64 через прокси. Референсы,
чьи URL ведут на собственный APP_URL в `/assets/model-references/`, тоже читаются
из локальных файлов и вкладываются в запрос. Таким образом FASHN не скачивает
ни исходник, ни наши стандартные референсы с российского VPS. Внешние референсы
по-прежнему должны быть доступны FASHN. Без прокси сохраняется режим временных URL.

После загрузки новой версии и изменения .env пересоздать контейнер:

```bash
cd /opt/vera-prive/deploy
docker compose up -d --build app
docker compose exec -T app node server/photo-diagnostics.mjs --probe
```

Диагностика показывает наличие прокси (без его адреса/пароля), проверку баланса и
два заведомо некорректных POST-запроса: 350 КБ и 3 МБ, чтобы проверить передачу
фото вместе с референсом. HTTP 400/422 в upload probe ожидаем: модель не существует,
поэтому платная генерация не создаётся. После успешных проверок запустить один
реальный кадр из формы товара и проверить его качество.
